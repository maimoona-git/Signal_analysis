# Test coverage: this port vs the native app's suite

The native app has **118 tests** (94 test functions, some parametrised) in 23 files. This
port has **399 automated tests** plus **608 recorded comparisons against the original** (five of the
84 pipeline scenarios now differ from the original on purpose -- see the notes at the bottom):

| Suite | Tests | Runs on | Command |
| --- | ---: | --- | --- |
| C++ core / pipeline / bridge (28 programs) | 310 (262 without the GUI widgets) | native; WASM under node | `ctest` |
| GUI widgets (`test_gui`, among the above) | 48 | desktop Qt, offscreen | `ctest` (native, needs Qt) |
| JS bridge + model + pipeline (`tests/bridge/*.test.mjs`) | 69 | WASM under node | `ctest` (`test_bridge_js`) |
| The browser app in real Chrome (`tests/gui/browser-gui.test.mjs`) | 19 (+1 opt-in) | headless Chrome | `ctest` (`test_browser_gui`) |
| The static site, relocated, stock server | 1 script (re-runs the 14) | headless Chrome | `ctest` (`test_static_site`) |
| ML chain smoke (`scripts/browser-smoke.sh`) | 11 captures + 2 pipelines | headless Chrome | manual |

Recorded from the **original native code** (`tests/data/`, regenerated by `ml/make_*fixtures.py`):
139 correlate + 251 fec + 44 interleave + 90 detect + 84 pipeline scenarios (each with the
original's outputs, errors and GUI text), and 11 ML preprocessing/classification cases. Every
port of a native function is compared against those, exactly.

## Beyond the native suite

Things the native app never needed and this port does:

- **Untrusted input.** Truncated/corrupted WAVs (every truncation + 2,000 corruptions), absurd chunk sizes,
  option validation at the JS boundary, malformed model output, a throwing classifier, out-of-memory.
- **Native ↔ WASM agreement.** Golden hashes for every encoder/modulator/interleaver; preprocessing compared
  across two different FFTs (fftw vs liquid-dsp's own).
- **The JS ↔ C++ boundary.** The ML call-out (concurrency, leaks, re-entrancy), file bytes in, heap growth.
- **The real browser.** A real file chooser, keyboard and mouse, no external requests, hosting under a
  sub-path, a stock static server, large captures (64 MB regression; 1 GB out-of-memory, opt-in).
- **Mutation checks.** In each phase, plausible bugs (flipped tie-breaks, wrong bit order, upside-down
  plots, dropped normalisation, uncapped text) were introduced on purpose to confirm the tests fail.

## Known limits (documented, not hidden)

- The shipped weights misclassify some modulations (`ml/README.md`); the tests check the port matches the original, not that the model is accurate.
- The original's LDPC decoder cannot correct single-bit errors at codeword positions 7, 9, 13, 15; that is
  reproduced faithfully. Its convolutional-interleaver + FEC detection did not recover the message; that one
  is now FIXED here (the four `*_convolutional_auto` pipeline records differ from the original on purpose).
- Very large captures fail with a clear out-of-memory message: measured before windowing, 512 MB (64M samples)
  analysed in about 2 s and 768 MB did not fit (the browser holds the capture, its samples and its spectrogram at once).
